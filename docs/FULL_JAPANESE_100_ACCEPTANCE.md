## 100%判定の原則

**日本語教材の100%**は、原本を逐語訳して合法的に配信するか、同等の学習到達目標をカバーする*独立執筆の包括的教材*を全76節に用意するか、いずれか適法な方法で実現する。いずれの場合も、各節で以下を満たすこと。

1. 原本目次のページ・節の境界、全学習到達目標と重要な式を出典側で確認し、参照先を記録する。
2. 本文・代表式の意味と導出、単位、初期条件・境界条件、適用可能な範囲、物性、注意すべき例外、必要な図解（独立作図または適切な許可済み素材）、数値例と手計算、確認問題を十分に扱う。原本の英語や日本語訳を許可なく転載しない。
3. 独立した確認者が重要な数値・式・符号、出典、著作権上の取り扱いを実際に確認し、承認日・根拠・修正履歴を残す。
4. アプリで日本語学習資料を読み進め、対応する問題を解き、検索・読了保存・読み上げ支援等を利用できることを確認する。

**問題集の100%**は、「324問になった」「全節に1問ずつ置いた」だけでは認めない。暫定の最低品質ゲートとして、各節8問以上、少なくとも3種類の認知的技能（概念理解、数値計算または式の評価、適用条件判断や設計など）を明示し、各問について以下を承認する。

- 設問条件が一意、正答が厳密、誤答がなぜ間違いか明確。
- 途中計算、単位・有効数字、近似条件、図・出典・改訂情報が追跡可能。
- 暗記だけに偏らず基礎、標準、発展、複合・設計判断を組み合わせる。数学的な数値計算を問うのが不自然な節には適切な説明・判断問題で代替する。
- 実際の独立レビューとアプリ内での回答・復習・保存の検証を行う。

8問という数字は自動監査の**最低ライン**であって、原本の学習範囲全体を網羅したという保証ではない。節の学習内容が多ければ8問を超える。編集者が節別の到達目標を明文化し、全目標を評価できることを別途確認する必要がある。

## 正確な現在値の出し方

```bash
node scripts/readiness-audit.mjs
node scripts/readiness-audit.mjs --json
node scripts/readiness-audit.mjs --strict
```

- 通常実行は**事実の報告**で終了コード0。各工程の件数を示す。
- `--strict` は上記の必須条件が全て成立していない場合、**終了コード1**で拒否する。現状では未達成なので失敗が正しい。
- `data/readiness-evidence.json` に権利の許可範囲、原本照合、出版社等の承認、第三者校閲の**実在する証跡だけ**を記録する。存在しない証跡を作らない。
- 公開可能な日本語全文教材と、非公開に保つ著作権上の内容を分離する。実体が移行していない旧PCの「下書きあり」46節はゼロから翻訳済みとして計上しない。
- `tests/readiness-audit.test.mjs` が、短い概念ノート・件数だけでは完成扱いにならないことを検査する。

## 達成のために必要な外部依存

- **旧PC教材の実体：** 44節分の下書きとローカル保管2節を安全な方法で回収し、保全・実物・レビュー状況を再確認する。記録だけを見て実体があると判断しない。
- **権利の文書：** PDFの公開許可が訳文・書籍原図単体まで及ぶとは限らない。許可範囲がない場合は独立執筆を優先し、全訳・原図を公開しない。
- **レビュー担当者：** AIの内部検算は学術専門家による第三者校閲の代わりにならない。未レビューの箇所を100%認定することは禁止。
- **実機検証：** iPhone Safari、オフライン再訪、音声支援等のアプリQAは教材の完成とは別枠で追跡する。

この基準の達成に必要な工程は大量であり、一度の自動生成やCI成功だけで100%にできない。完成を主張する前に `--strict` と人による実証を両方通す。
