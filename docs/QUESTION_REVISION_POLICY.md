# 問題改訂と復習成績の扱い（2026-10-28）

## 目的
問題の設問、選択肢、正答、適用条件を変更したあと、**過去の別版の正答を新しい問題の正答として集計しない**。古い学習履歴自体は消さず、復旧・監査可能な状態を維持する。これは出題範囲の網羅率、原本訳文の完成率、受験者の実力の証明ではない。

## 改訂番号の契約
- `data/questions.json` の `revision` は任意の英数字識別子。省略された問題は従来どおり `initial` 版として扱う。
- **問題の意味を変える変更時**（正答、選択肢、仮定、問い、数値、適用境界の変更など）は、同じ問題IDを保持するなら `revision` を新しい一意の識別子へ進める。例：`"revision":"v2"`。
- 解説の単純な誤字修正など、正誤判断に影響しない変更では必ずしも改訂番号を変える必要はない。ただし学習履歴の比較が危ういときは安全側で改訂する。
- `revision` は最大48文字の半角英数字、ピリオド、アンダースコア、ハイフン。先頭は英数字。公開ビルドでは不正な形式を拒否する。
- 出題後に保存する回答履歴の `questionRevision` はその設問の `revision`、未指定時は `initial` とする。旧記録でこのキーがない場合は `initial` として比較し、既存データの後方互換性を維持する。
- `questionFingerprint` による中断セットの再開時チェックも保持する。**教材を改訂した際にrevisionを上げなければ、既存の回答記録の意味までは自動で検知できない**ので、編集者による改訂番号運用は必須。

## 学習者画面と復習
- 分野マップと章別ロードマップは**現在版に合致する問題の最新回答**で成績を計算する。古い版の回答は「改訂前の回答」として別に件数を表示する。
- 改訂後の再回答がない問題は「回答済み・正解」から外し、「再回答が必要」として復習候補へ送る。
- 問題を再回答した時は、古い版で蓄積した連続正解日数を流用せず、現行版の履歴だけで次回復習までの間隔を計算する。
- 章別ロードマップには「未回答」「最新誤答」「改訂前の回答」を分けて出す。「未正解・未回答を優先」は **改訂前の回答→最新誤答→完全未回答** の順に最大10問を出題する。既存の「章の全問題」も残す。
- レビューが必要な問題の優先順位は学習の操作支援にすぎず、試験合格可能性の確率を意味しない。

## テストと制約
- `tests/core.test.mjs`：分野指標が旧版正解を誤集計しないこと、保存データの後方互換性、壊れた改訂番号の検出。
- `tests/chapter-curriculum.test.mjs`：11章・章別関連付け、旧版正解・現行誤答・未回答の区別と優先順。
- `tests/public-content-contract.test.mjs`：公開教材の不正な改訂番号の拒否。
- `tests/browser-distribution.mjs`：章別ロードマップからの優先演習と従来の全問演習、既存保存・復元導線の回帰検証。
- 章別演習の問題はアプリ独立作成教材と一部の書籍出典問題であり、日本語訳76節の完成率は変わらない。
- iPhone Safari実機、画面読み上げ、WebKitオフライン再訪、専門家による学術査読は本作業のみで完了とは扱わない。
